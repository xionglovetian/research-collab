# 豆包电脑版怎么参与

**结论：豆包装不了这个 Skill，也不能自己调用它。** 它没有插件目录、读不到本地文件、执行不了脚本。
豆包参与的方式是**接收文本**——所有上下文由 DSH 整理好交给它。

两种接入强度：

| 做法 | 你要做什么 | 效果 |
|---|---|---|
| **人工（默认）** | 一次性设定常驻纪律 + 每次粘贴 make_brief 生成的包 | 现在就能用，无需任何配置 |
| **全自动** | 配一个火山引擎方舟 API Key | DSH 直接调豆包模型，结果自动落盘 + 核查 |

先看人工方式（第一节到第三节），想要免粘贴就跳到 [三·五](#三五全自动让-dsh-直接调用豆包模型)。

---

## 一、一次性设定：把常驻纪律粘进豆包

如果 豆包电脑版 有「自定义指令 / 智能体 / 角色设定 / 系统提示」这类入口，把下面整段贴进去。
没有这个入口也没关系——每次开新对话时，把它作为第一段发过去即可。

```text
你是中文学术写作助手，负责把已经确定的证据写成通顺、克制、可发表的正文。你不做研究判断，不补充事实。

三条铁律，任何情况下不得违反：
1. 不得新增任何数字、百分比、年份、样本量、文献或结论。需要数字时，只能使用我给出的证据表里带编号的条目，并在引用处标注（C01）这样的编号。
2. 不得改变结论强度：标为「估计/假定」的只能写"估计/假定/可能"，不得写成"表明/证明/说明"；不得把"相关"写成"因果"；不得从单一样本外推到整体。
3. 我给的证据不够时，写占位符 [待补:具体缺什么]，不要自己补、不要猜、不要用"约/近/超过"含糊过去。

写作要求：
- 学术书面语，第三人称，不要排比与破折号堆砌。
- 每段只承担一个论点，段首句即论点。
- 不使用"众所周知""毋庸置疑""具有重大意义"这类空泛评价。
- 不出现"作为AI""根据您提供的资料""希望对您有帮助"这类元话语。
- 结尾不写"综上所述"，除非我明确要求写小结。

收到任务时，先用一行确认：要写的章节、字数、可用的证据编号。然后直接写，不要反复追问。
```

---

## 二、每次任务：粘贴 DSH 生成的包

在项目里运行（DSH 会替你跑）：

```powershell
python scripts/make_brief.py --project . --stage G4 --to doubao                 # 叙事反馈
python scripts/make_brief.py --project . --stage G5 --to doubao --section 3.2   # 写某一节
```

生成的文件在 `handoffs/G4_doubao_<日期>.md` 或 `G5_doubao_<日期>_<节号>.md`。
**把整份内容复制进豆包对话框**——它里面已经包含：题目、语体、字数预算、本节大纲要求、可用证据表（带编号与强度）、禁写清单。

豆包看不到任何文件，所以**不要**只发一个路径或"见附件"，那样它只会按常识编。

## 三、收回来之后

把豆包的输出整段贴回给 DSH，说"这是豆包的结果"。DSH 会：

1. 落盘到 `05_draft/v<N>_<section>.md`（文件头记 `author: doubao` / `saved_by: dsh`）
2. 跑 `claim_check.py` 核对每个数字是否可追溯到 `claims.csv`、有没有把假设写成实证
3. 有问题就一次性列清退回，只改必须改的点

## 三·五、全自动：让 DSH 直接调用豆包模型

上面两步都要人工复制粘贴。如果你有**火山引擎方舟（Ark）**的 API Key，可以让 DSH 直接调用豆包模型，省掉搬运：

```powershell
$env:ARK_API_KEY="你的 key"
$env:ARK_MODEL="doubao-pro-32k"        # 或你的接入点 ep-xxxx

python scripts/make_brief.py --project . --stage G5 --to doubao --section 3.2 --via api
```

它做的事：

1. 用 `integrations/doubao.md` 里那段常驻纪律作 **system prompt**——等于把这个 skill 的写作纪律装进豆包
2. 用 make_brief 生成的包作 **user message**（含证据表、大纲要求、禁写清单）
3. 拿回结果直接落盘到 `05_draft/`，frontmatter 记 `via: api` / `model` / `claim_check: pending`
4. 打印该跑的 `claim_check.py` 命令

**注意**：`--via api` 只适用于 `--to doubao`。Codex 是能读文件的 agent，不需要也没法这样调。

缺 key 时会 `exit 5` 并给配置指引，同时**保留已生成的提示词包**，可以退回手工粘贴——不会卡死。

| 方式 | 需要什么 | 人工量 |
|---|---|---|
| `--via paste`（默认） | 无 | 复制粘贴两趟 |
| `--via api` | Ark API Key + 模型 ID | 一条命令 |

## 四、为什么不能让豆包"自己装"

| 能力 | DSH | Codex | 豆包电脑版 |
|---|---|---|---|
| 读本地文件 | ✓ | ✓ | ✗ |
| 执行脚本 | ✓ | ✓ | ✗ |
| 有 skill 目录 | ✓ `~/.agents/skills` | ✓ `~/.codex/skills` | ✗ |
| 维护工作区 | ✓ | 部分 | ✗ |

豆包是这条流水线里唯一"纯语言"的一端。它的价值在于中文长文的语感，不在执行。**让它只做它擅长的**：判断这些结果该怎么讲，以及把已确认的证据写成正文。

这也是流程里 DSH 必须替它搬运内容、并在收稿后做数字核查的原因——它没有能力自查。

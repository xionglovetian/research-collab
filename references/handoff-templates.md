# 交接提示词包 — 模板与话术

三方没有共享记忆，所以每一棒都要给一个**自足**的提示词包。判断标准：**把它交给一个从没听过这个项目的聪明人，他也能独立完成这一棒。**

存放：`handoffs/<阶段>_<目标>_<YYYYMMDD>.md`。一个包只服务一棒。

---

## 〇、两个必须遵守的填充规则

**规则 1：`{公共区}` 要换成真实路径。**
公共区位置不是固定的（项目内 `shared/`、共享盘、网盘都可能），真实值在项目 `state.yaml` 的 `shared_dir`。本文件所有 `{公共区}/xxx` 在生成交接包时都要替换成实际路径（给能读文件的工具用**绝对路径**，最省歧义）。

**规则 2：豆包读不到任何文件，所以给豆包的包里不能只写路径。**
| 目标 | 给路径还是给内容 |
|---|---|
| Codex | 给路径即可（它能读工作区），必要时再贴关键片段 |
| DSH | 自己就是执行方，直接读文件 |
| **豆包** | **必须把内容贴进包里**——路线、大纲、claim 清单、相关 chat 原文，一个都不能只写路径 |

给豆包的包里出现"见 `{公共区}/outline.md`"这种句子，等于什么都没给。它只会根据常识编。

> **别手搓**：`python scripts/make_brief.py --project . --stage G4/G5 --to doubao` 会把这些内容自动拼好（路线、大纲、台账，且写正文时排除 `assumption`）。下面的模板是它的依据，也是你手改时的参照。

**规则 3：每包两行**——`上游：{上一棒产出}` / `下一棒：{谁 + 要拿什么}`。

## 一、四要素

| 要素 | 写什么 | 常见错误 |
|---|---|---|
| **目标** | 这一棒只产出什么，一句话 | 写成"帮我完善论文"（范围过大，必跑偏） |
| **输入** | 明确列出要读者读的文件（路径 + 一句说明），或把最短必要片段直接贴进去 | 让工具去"找一下相关资料" |
| **输出** | 确切文件名、章节层级、字数区间、必须包含的要素 | 只说"写详细点" |
| **禁区** | 不许新增数字/文献/结论，不许改 claim 强度，不许外推 | 只在末尾轻描淡写提一句 |

**长度纪律**：给 Codex 的包 ≤ 2 屏（它要的是约束和取舍空间，不是素材量）；给豆包**必须自足**——它读不到任何文件，宁可多贴一段，也别让它"根据常识补充"。

## 二、给 Codex：立项 / 路线 / 大纲

```
# 角色
你是本项目的科研规划者。你只负责研究路线与大纲，不写代码、不写正文、不编造数据。

# 项目
题目：{title}
用途：{target}（中文核心期刊论文 / 国自然本子 / 学位论文章节 / 英文 SCI）
语言与字数：{language} / 正文约 {word_budget} 字
已有数据：{data_summary 或"暂无，需设计获取方案"}
截止时间：{deadline}

# 本次目标（只做这一件）
{例如：产出一份可执行的技术路线，含研究问题、创新点、分阶段实验设计、风险与备选方案}

# 必须回答
1. 研究问题：用一句话写清"谁在什么条件下会导致什么"。
2. 与现有工作的差异点；若没有差异点，直说"创新性不足"并给替代方向。
3. 数据/实验如何支撑每一个结论？哪些结论现有数据支撑不了？
4. 最大风险是什么？失败时的降级方案是什么？

# 输出：写入 `{公共区}/route.md`
## 研究问题
## 创新点（≤3 条，每条一句可证伪的断言）
## 技术路线（分阶段，每阶段：输入→方法→产出→验收标准）
## 需要的证据清单（供 DSH 建台账与排实施顺序）
| claim 描述 | 预期量纲 | 数据来源 | 优先级 |
## 风险与降级方案
## 不建议做的方向

# 然后
在 `{公共区}/chat.md` 追加一条消息，类型 `进度`，`@dsh @doubao`，说明路线已就绪、
DSH 需在 G3 前确认哪些证据缺数据、豆包需在 G4 前读完大纲。
格式见 `references/chat-protocol.md`。

# 禁区
- 不编造数据、文献或已有结果。
- 不输出大段论文正文；需要时只给结构骨架。
- 证据清单里每条必须能被数据支撑或被标为"需新增实验"。
```

**注意**：路线文件位于**公共区**（位置见 `state.yaml` 的 `shared_dir`），是三方共读的公共黑板。你（Codex）是唯一写入方；DSH 只校验、不修改。用户确认后由 DSH 执行 `check_shared.py --freeze`。

大纲阶段把"本次目标"换成大纲，输出改为 `{公共区}/outline.md`：

```
## 章节大纲
每节：序号 | 标题 | 目的 | 目标字数 | 需要的 claim 编号或需求 | 关键图表
## 各节之间的逻辑衔接（一句话/节）
## 需要 DSH 先补齐的证据（优先级排序）
```

## 三、给豆包：研究产出反馈与写作意图（G4，核心新增）

这一棒**不写正文**。豆包的任务是"读完这些结果，告诉我这篇论文该写什么"。它是全流程里最容易被忽略、但对成稿质量影响最大的一步。

豆包看不到文件，所以 DSH 必须把**结果简报**整理进包里（表格转成 markdown、图转成文字描述 + 可用图片附件）。

```
# 角色
你是中文科研写作顾问。你读研究产出，判断这篇论文「该讲什么故事、每一节该写什么、哪些话现在还不能写」。
你不做研究判断、不补数据、不写正文。

# 项目
题目：{title}
用途：{target} ｜ 语言：{language} ｜ 正文字数预算：{word_budget}
研究问题（来自已冻结路线）：{research_question}
创新点（来自已冻结路线）：{innovations}

# 研究产出（DSH 实施结果，这是全部事实来源）
## 数据与处理
{n_samples}，{methods_summary}

## 主要结果表
| 编号 | 事实 | 数值/口径 | 强度 | 出处 |
|---|---|---|---|---|
| C01 | ... | 92.3% | measured | tables/main.csv |
| C05 | ... | — | assumption | 情景推算 |

## 图表
- 图 1：{图描述}，用来证明 {对应 claim}
- 图 2：{图描述}，用来证明 {对应 claim}

## 已知缺口
- {缺什么，DSH 与 Codex 已确认/未确认}

# 章节大纲（Codex 已定，你可以提出冲突但不许自行改写）
{outline 摘要}

# 只回答这五个问题
1. **主故事**：这篇论文一句话在讲什么？依据哪几个 claim 编号？（必须给编号）
2. **每节该写什么**：按大纲逐节，写"这一节要证明什么、用哪几个 claim、不要写什么"。
3. **现在写不出来的**：哪些结论缺证据、只能写"提示"不能写"证明"、或必须删掉？
4. **叙事顺序与图表**：建议的论证顺序，图 1/2/3 各自承担什么。
5. **与大纲的冲突**：大纲要求但结果支撑不了的，逐条列出，并给"删 / 降级 / 补做"建议。

# 严禁
1. 不得新增任何数字、样本量、年份；需要数字时只能引用上表编号。
2. 不得新增文献。
3. 不得把 `assumption` 写成"发现"，不得把相关写成因果。
4. 不得直接写正文段落（这一棒只出决策）。
5. 不得改写大纲；有冲突只提建议。

# 输出：`05_draft/narrative_{YYYYMMDD}.md`
## 主故事
## 分节写作决策
| 节 | 要证明什么 | 用哪些 claim | 不要写什么 |
## 现在写不出来的
## 建议图表顺序
## 与大纲的冲突
```

**收稿后 DSH 必做**：核对豆包引用的每个 claim 编号是否真实存在 → 冲突项抛 `chat.md` 给 Codex 裁决 → 用 `decisions.md` 沉淀定稿决策。

## 四、给豆包：章节初稿（G5）

**一次只写一节。** 必须带上 G4 已确认的分节决策。

```
# 角色
你是中文学术写作助手，负责把已确定的证据写成通顺、克制、可发表的正文。你不做研究判断，不补充事实。

# 写作对象
题目：{title} ｜ 期刊/用途：{target}
语体：{例如：中文核心期刊，第三人称，学术书面语，不过度使用破折号与排比}
全文字数预算：{word_budget}；本节预算：{section_budget} 字（±10%）

# 本次只写这一节
章节：{例如：3.2 结果与分析 — 影响因素}
在全文中承担的作用：{一句}
G4 已确认的本节决策：{要证明什么 / 用哪些 claim / 不要写什么}
上一节结尾（衔接参考）："{last_paragraph_tail}"

# 可用证据（只许使用以下事实，编号必须出现在引用处）
| 编号 | 事实 | 数值/口径 | 强度 |
|---|---|---|---|
| C01 | {claim} | {value unit} | measured |
| C02 | {claim} | {value unit} | derived |

# 严禁
1. 不得新增任何数字、百分比、年份、样本量——包括"约""近""超过"这类模糊化改写。
2. 不得新增文献引用；需要而证据表里没有的，写 `[待补:文献-xxx]`。
3. 不得改变强度：`assumption` 只能写"估计/假定"，不得写成"表明/证明"。
4. 不得把相关写成因果；不得从单一样本外推到整体。
5. 不得使用"众所周知""毋庸置疑""具有重大意义"等空泛评价。
6. 不得出现"作为 AI 模型""根据您提供的资料"等元话语。

# 输出格式
- Markdown，从 `### ` 三级标题开始（不要自带一级标题）。
- 每段只承担一个论点，段首句即论点。
- 首次出现某证据时用「（C01）」标注。
- 数据不足处保留占位符 `[待补:2023年产量数据]`，不要自己填。
- 结尾不写"综上所述"，除非大纲明确要求本节小结。
```

**收稿后 DSH 四件事**：按版本号落盘（不覆盖）→ 跑 `claim_check.py` → 数一遍字数与占位符残留 → 一次列清问题退回。退回只指出**必须改的点**，不夹带风格偏好。

## 五、给豆包：润色 / 压缩 / 去 AI 味

```
# 任务
对下面这段已定稿正文做语言层面处理，**不得改变任何事实与结论强度**。

# 只允许改
句子长度与节奏、连接词、冗余修饰、重复表述、被动改主动、术语首次出现的中英文对照。

# 绝对不许改
数字、单位、样本量、因果方向、情态动词强度（可以→可能、表明→提示 都算改强度）、段落论点顺序、证据编号。

# 目标
{例如：压缩 15%，学术书面语，去掉翻译腔与排比；或：把 3 处"表明"降级为"提示"}

# 原文
{原文}

# 输出
先给改写稿，再单独列一张「改动说明」表：原句片段 | 改后 | 改动理由（一句话）。
```

改动说明表是验收接口：DSH 扫这张表就能判断有没有越界，不必逐字对比。

## 六、给 Codex：成稿评审（G6）

```
# 角色
你是该刊物的审稿人，标准从严。只评审，不改写。

# 材料
- 路线：{公共区}/route.md（已冻结）
- 大纲：{公共区}/outline.md（已冻结）
- 叙事决策：05_draft/narrative_{日期}.md
- 成稿：05_draft/{files}
- 证据台账：04_results/claims.csv

# 只查四类问题
1. **对齐**：正文是否回答了 route 的研究问题？大纲有、正文缺的有哪些？
2. **过度声称**：哪些结论超出了台账 claim 的强度或适用范围？（逐条给原文 + 台账编号）
3. **证据缺口**：哪些断言没有任何台账条目支撑？
4. **审稿人会问什么**：列 5 条最可能被质疑的点，按杀伤力排序。

# 输出：`06_review/review_{YYYYMMDD}.md`
## 结论（接收/小修/大修/重做 + 一句话理由）
## 必须修改（位置 | 问题 | 具体改法）
## 建议修改
## 审稿人最可能追问的 5 个问题（附建议答法）
## 不建议再动的地方

# 禁区
不重写全文；不提出需要新数据的要求而不标明"需回 G3 补做"。
```

## 七、DSH 往 `chat.md` 报进度

每完成一个实施阶段就追加一条，让 Codex 和豆包知道发生了什么（豆包由 DSH 转述）：

```markdown
## #NNN · {时间} · dsh · 进度

@codex @doubao

{做了什么} → 产出 `{文件}`、台账 {Cxx–Cyy}。
关键结果：{一句话，附 claim 编号}。
风险/缺口：{若无可写"无"}。

- 下一步：{进入哪一棒}
```

阻塞时用类型 `阻塞`，把"需要谁做什么决定"写成二选一，别让对方做开放题。

---

## 八、包与包的衔接

- 每个含 `上游：` / `下一棒：` 两行，方便在 `handoffs/` 里顺藤摸瓜。
- 目标工具换了（本来给豆包、改给 Codex）就**新建包**，不要就地改，历史留档才能复盘。
- 用户临时口头想法若影响路线，先记 `state.yaml.open_questions` 或抛 `chat.md`，等 Codex 裁决，别当场改主线。

# 证据台账（claims ledger）

台账是三方协作的**唯一数字来源**。豆包写的每个数字都必须能在台账里查到一行；查不到就是幻觉。

文件：`04_results/claims.csv`（UTF-8，逗号分隔，首行表头）。

---

## 一、字段

| 字段 | 必填 | 含义 | 示例 |
|---|---|---|---|
| `id` | 是 | 唯一编号，`C01` 起顺序编排，永不复用（删条目也不回收编号） | `C07` |
| `claim` | 是 | 一句话事实，可独立读懂 | `处理组平均产量高于对照组` |
| `value` | 否 | 数值本体；无单一数值时留空，写进 `claim` | `92.3` |
| `unit` | 否 | 量纲/口径 | `%` / `t·hm⁻²` / `元/亩` |
| `strength` | 是 | `measured` / `derived` / `literature` / `assumption` | `measured` |
| `source` | 是 | 可追溯出处：文件:定位，或 `doi:`/`GB/T 7714 引文` | `tables/main.csv:row12` |
| `allowed_in` | 是 | 允许出现的位置，分号分隔 | `results;abstract;discussion` |
| `note` | 否 | 口径说明、换算方式、局限 | `n=3 生物学重复；小区面积 20 m²` |

`allowed_in` 取值：`abstract` / `intro` / `results` / `discussion` / `conclusion` / `methods`。留空视为 `results;discussion`。

---

## 二、强度判定（决定能不能用强动词）

| 强度 | 定义 | 判据 | 允许的动词 | 禁止 |
|---|---|---|---|---|
| `measured` | 本研究数据直接测得 | 有原始数据文件可查 | 提高/降低/达到/呈显著差异 | 超出样本范围的推广 |
| `derived` | 由 measured 经计算、建模或换算得到 | 换算口径可复现 | 据此推算/折算/拟合得到 | 隐去换算口径直接当实测 |
| `literature` | 他人已发表结果 | 有 DOI 或完整引文 | 已有研究表明/据 X 报道 | 与本文发现混为一谈、当作本文结论 |
| `assumption` | 假设、情景设定或估算 | 有明确假设前提 | 假定/估计/按 X 情景推算 | 进摘要结论；写成"发现" |

**升级是硬红线**：`assumption` → `measured`、`literature` → 本文结论、`相关` → `因果`，都必须先有新的 DSH 分析结果，重新登记新条目，不能就地改强度。

---

## 三、怎么生成台账（DSH 视角）

不要手工敲数字，从结果文件里程序化生成，避免转录错误：

1. 跑完分析后，把关键指标导出为 `04_results/tables/*.csv`，每行一个统计量。
2. 写一个 `03_code/make_claims.py`：读 tables → 按固定规则生成 `claims.csv` 行 → 保留已有 id（幂等）。已有 id 不重排，新增条目追加到末尾。
3. 人工只做两件事：补 `strength` 与 `allowed_in`，补 `note` 里的口径。
4. 生成后跑一遍自检：`allowed_in=abstract` 的条目里不得出现 `assumption`。

台账更新后，凡引用旧数值的草稿都要重核——这是 G4 每个版本都要跑的。

---

## 四、核查草稿

```powershell
python "${SKILL_DIR}/scripts/claim_check.py" --draft 05_draft/v2_results.md --claims 04_results/claims.csv
```

脚本做三件事：

1. 抽取草稿中所有数值（含百分数、区间、科学计数、`±`），逐个与台账 `value` 比对（同一单位下按数值等价，允许 `--tol` 容差）。
2. 报告**未匹配数字**（疑似幻觉，逐条给出上下文）与**台账未被使用条目**（可能是漏写的发现）。
3. 检查强度违规：`assumption` 条目所在的句子若出现"证明/表明/证实"，或出现在 `abstract`，标为违规。

退出码：`0` 全部匹配；`1` 存在未匹配或违规（便于批量流水线里作门禁用）；`2` 输入错误。

**已自动归一化、不会误报的内容**：Markdown 标题与章节序号（`### 3.2`）、图表编号、文献角标 `[1]`、URL、代码块、claim 编号（`C01`）、量纲指数（`kg·hm-2`、`m^2`）、千分位、科学计数（`1.2×10^5`、`10^5`）、区间（`85–93` 拆成两端分别核对）、1900–2100 的 4 位年份。

**仍需人工豁免的用 `--ignore`**（可重复）：

```powershell
python claim_check.py --draft 05_draft/v1_results.md --claims 04_results/claims.csv `
  --ignore 'n\s*=\s*\d+' --ignore 'GB/T\s*\d+' --ignore '见\s*\d+(?:\.\d+)*\s*节'
```

**单位换算**：只自动接受"台账存小数、正文写百分数"（`0.923` ↔ `92.3%`），并标注「按百分比换算」提示复核。反向口径（台账 `85`、正文 `0.85`）会报未匹配——这是故意的：那本来就是单位错误。

处理原则：**任何未匹配数字都必须有结论**——要么补进台账（它是真的），要么改写（它是编的）。不许"看着差不多就放过"。

---

## 五、常见坑

- **单位混用**：台账 `%`、正文写"九成"或"0.92"。比对会失败，这是特性不是 bug——逼你统一口径。
- **四舍五入分歧**：台账 `92.31`、正文 `92.3%`。用 `--tol 0.05`，别改台账去迁就文风。
- **范围数字**：`85–93%` 这类区间，台账里存两端各一条，正文引用两个编号。
- **图表里的数字**：图注与正文数字同源，同样要过台账。
- **年份与编号**：脚本默认白名单化 4 位年份、1–2 位序号，避免误报；`--no-whitelist` 可关闭。

# 对话文件协议 — `shared/chat.md`

三个智能体没有共享记忆，`chat.md` 就是它们的**对话记录**。它同时承担三件事：留痕（谁在何时说了什么）、寻址（这句话要谁回应）、收敛（分歧最终怎么裁）。

**唯一铁律：只能追加，永不修改或删除他人消息。** 想推翻某句话，就追加一条新消息说"我不同意 #012"，而不是回去改 #012。

---

## 一、消息格式

```markdown
## #014 · 2026-10-17 14:32 · codex · 裁决

@dsh @doubao

回应: #012

路线第 3 阶段改为"先做敏感性分析再建模"，理由：#012 指出的样本量不足以支撑分组比较。

- 影响：`03_code/` 需新增 `sensitivity.py`，产出 `04_results/tables/sens.csv`
- 时间：G3 前完成
- 状态：待 DSH 执行
```

**头行固定四段**，用 ` · ` 分隔：

| 段 | 取值 | 说明 |
|---|---|---|
| 编号 | `#014` | 递增，DSH 维护；不知道下一个就查 `check_shared.py` |
| 时间 | `2026-10-17 14:32` | 本地时间，精确到分 |
| 作者 | `codex` / `dsh` / `doubao` / `user` | 只写这四个 |
| 类型 | 提案 / 进度 / 提问 / 反馈 / 阻塞 / 裁决 | 见下表 |

**类型说明**：

| 类型 | 谁用 | 用途 |
|---|---|---|
| `提案` | 任一方 | 想改路线、大纲、方法论 |
| `进度` | DSH 为主 | 实施到哪了、产出是什么、验收如何 |
| `提问` | 任一方 | 缺信息，需要特定人回答 |
| `反馈` | 豆包为主 | 结果解读、论文该写什么、哪些结论写不出来 |
| `阻塞` | 任一方 | 卡住了，必须有人处理才能继续 |
| `裁决` | Codex / user | 对提案或分歧给出结论，具有终局性 |

**正文约定**（都用得上就都写，但保持短）：

- `@某人` — 要谁回应；可多人
- `回应: #NNN` — 这是对哪条的回应
- `关闭: #NNN` — 宣告某条议题终结（裁决或用户拍板后）
- `引用: 路径#小节` — 指向文件依据，如 `shared/route.md#技术路线`
- `状态: 待处理 / 待回应 / 已完成` — 给人看的提示，不作程序判据

---

## 二、"还在等谁"是怎么判定的

程序只认三条规则（`check_shared.py --for <agent>` 按此计算）：

1. 消息里有 `@该agent`；
2. 该消息的作者不是该 agent 本人；
3. **之后没有**任何消息包含 `回应: #该消息编号` 或 `关闭: #该消息编号`。

所以：回应一条消息，唯一有效的做法是追加一条带 `回应: #NNN` 的新消息。只在口头上说"我回过了"不算。

`状态:` 行只是给人看的，写错了不影响判定，但会误导人，请如实写。

## 三、六个典型消息

**① Codex 交付路线（G1）**
```markdown
## #001 · 2026-10-17 10:05 · codex · 进度

@dsh @doubao

路线与大纲已写入 `shared/route.md`、`shared/outline.md`。

- 研究问题：施肥强度如何影响产量稳定性
- 证据需求：见 route「需要的证据清单」，共 6 条
- 请 @dsh 在 G3 前判断哪些缺数据；请 @doubao 在 G4 前看完大纲，准备叙事反馈
- 状态：待 DSH 冻结
```

**② DSH 报阻塞**
```markdown
## #002 · 2026-10-17 11:20 · dsh · 阻塞

@codex

回应: #001

证据需求第 4 条（2023 年产量）在 `02_data/raw/` 中不存在，无法实施。
两条路：① 你确认删去该节；② 授权我用公开统计年鉴替代并在台账标 `literature`。

- 在裁决前我继续做第 1–3 条，不停工
- 状态：待 codex 裁决
```

**③ Codex 裁决**
```markdown
## #003 · 2026-10-17 12:02 · codex · 裁决

@dsh

回应: #002

走方案 ②，但须满足：
- 只用省级年鉴，且台账 `strength` 标 `literature`、`allowed_in` 只给 `intro;discussion`
- 正文不得写成"本研究发现"
- `route.md` 已同步更新，请重新 `--freeze`

- 状态：待 DSH 执行
```

**④ DSH 报进度**
```markdown
## #004 · 2026-10-17 16:40 · dsh · 进度

@codex @doubao

回应: #003

G3 完成。产出：`04_results/tables/main.csv`、`figures/fig1.pdf`、台账 12 条（C01–C12）。
关键结果：处理组产量 92.3%，较对照高 18.6%（C01、C02，measured）。

- @doubao 结果简报见 `handoffs/G4_doubao_20261017.md`
- 状态：待 doubao 叙事反馈
```

**⑤ 豆包叙事反馈（经 DSH 代录）**
```markdown
## #005 · 2026-10-17 18:15 · doubao · 反馈

@codex @dsh

（经 dsh 代录）

读完结果，「主故事」建议定为：产量提升主要来自穗数而非粒重（C03、C05，measured）。
理由：两条 claim 强度都够，且与路线创新点 1 直接对应。

- 写不出来的：机制解释缺中介变量证据（台账无对应条目），讨论里只能写"提示"不能写"证明"
- 建议补做：若要做机制，需 DSH 增加中介检验 → 请 @codex 判断是否值得
- 状态：待回应
```

**⑥ 用户拍板收尾**
```markdown
## #006 · 2026-10-17 19:00 · user · 裁决

@codex @doubao @dsh

关闭: #005

不做机制，按豆包的主故事写，讨论里限定为"提示"。
@dsh 进入 G5，先写结果节。
```

## 四、谁能直接看到什么

| 谁 | 能否直接读 `chat.md` | 注意 |
|---|---|---|
| Codex | 能（有文件访问） | 动工前读末尾 + `decisions.md` |
| DSH | 能 | 负责维护编号、格式、归档 |
| 豆包 | **不能** | DSH 必须在交接包里**贴入相关消息原文** |

这是最容易出错的地方：以为在 `chat.md` 里 @了豆包，它就知道了。**没有 DSH 转述，豆包永远不知道。**

---

## 五、维护纪律（DSH 负责）

1. **编号**：追加前先查下一个编号，避免重号。重号会让 `回应:` 指错对象。
2. **代录**：豆包的输出由 DSH 落盘时，正文开头加 `（经 dsh 代录）`，保留原话，不改写。
3. **只记决定与分歧**：日常琐事（"已运行脚本"）不进 chat；进 `state.yaml` 的 `next_actions` 就够。
4. **沉淀**：一条议题关闭后，把结论写进 `shared/decisions.md`（一行一条，带编号），chat 里不必回头整理。
5. **归档**：chat 超过 200 条时，DSH 把前 150 条移到 `shared/chat_archive_<日期>.md`，在 chat 顶部留一行指向归档文件。归档文件同样不可修改。
6. **格式修复**：只允许 DSH 修正明显格式错误（如缺头行），且必须在同一条消息里注明"经 dsh 格式修复"，不得改内容。

## 六、反模式

- ❌ 回去编辑别人写过的消息（包括"帮他把错别字改掉"）→ 对话失去可信度。
- ❌ 用 `状态: 已完成` 代替 `回应: #NNN` → 程序判不出，议题会一直挂着。
- ❌ 把整份 chat 塞给豆包 → 浪费且稀释；只贴相关几条。
- ❌ chat 里做拉票式长文 → 一条消息一件事，超过 15 行就该拆或改写进文件。
- ❌ 用 chat 传数据、传代码 → 一律落文件，chat 里只放路径。
